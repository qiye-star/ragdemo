# 公告接入实施计划（巨潮全文为主 + Wind/iFind 降级，分市场路由）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 110 家上市实体（A 股 59、港股 12、美股 23、台股/其他上市地报 SEC 的 3 家 ADR）的公告
按市场分源、每日自动增量入库一张统一的公告目录；**只对海光信息（688041.SH）、浪潮信息
（000977.SZ）两家下载 PDF 并解析成文本块**，验证效果与成本后再决定扩大范围；其余实体先建
目录（标题、日期、链接），全文按需随时补下载解析。

**架构：** 新增一张时点表 `core.announcement_index`（公告目录），每份公告一行、不论来源、
不论市场。按 `core.entity.market` 路由到不同的主源：A 股走巨潮资讯网（全文），港股走港交所
披露易前端接口（全文），美股与在 SEC 报送的 ADR（台积电、日月光、阿里巴巴、百度、金山云）
走 EDGAR（全文，复用已有 `edgar_docs.py`）。A 股主源不可用时 Wind / iFind 顶上目录，全文记
入待补清单。分工沿用 ADR-0012 的路由框架（`ragdemo.sources`），冷却、降级、待补都是现成
机制。日本（东京电子、爱德万、信越）、韩国（三星、SK 海力士、韩美）需要你注册
EDINET / OpenDART 的免费 API key 才能接入，本计划先把适配器写好、接口留空，接了 key 直接用；
台股 7 家（联发科、鸿海等）除已报 SEC 的日月光外暂缓，官方 OpenAPI 只有当天数据、无历史、
无 PDF，够不上"全文可溯源"的要求。

**技术栈：** Python 3.11、psycopg 3、Dagster、httpx；新增依赖 `pypdf`（解析前本地读页数，
用于费用估算）。

**依据：** `docs/adr/0012-data-source-roles-and-degradation.md`、
`docs/adr/0013-cninfo-primary-announcement-source.md`（本计划修订其分工一节）、
负责人 2026-09-28 决定：D1–D5 采用建议、D2 收窄为"只解析 2 家试点"、
`docs/9.28-plan/验收记录/phase-2.md` 与本计划"实测记录"一节的结果。

## 全局约束（每个任务都隐含遵守）

- 对外查询强制 `as_of`；`known_at` = 现实中最早可知时刻。巨潮 / 港交所披露易只有日 /
  分钟精度时用保守上界；EDGAR 有秒级 `acceptanceDateTime`，直接用，**不是入库时间**。
- 每次供应商调用都记 `provider_snapshot`（`tests/test_snapshot_coverage.py` 静态守卫）。
- 时点表只追加：更正 / 取代记 `superseded_at`，不删行；新表登记 `core.bitemporal_registry`
  并配 `asof` 视图，`app_read` 不得直读基表。
- 数值不由模型产生；本计划不涉及任何模型调用（表格描述器已有，不改）。
- 密钥只在环境变量 / 代理层；巨潮、EDGAR、港交所披露易前端接口无需鉴权，直连。
- 访问任何官方 / 半官方接口都带**诚实的 User-Agent**（组织名 + 联系方式，不伪装浏览器）——
  2026-09-28 实测确认：SEC 对`www.sec.gov` 静态文件也按 UA 拒绝（无联系方式的 UA 收到 403，
  带联系方式的收到 200），这不是可选的礼貌，是会被执行的门槛。
- 解析走 TextIn（0.04 元/页）：每次 run 受 `PageBudget` 约束，月度受
  `RAGDEMO_MONTHLY_BUDGET_CNY`（默认 5000）80% 预警 / 100% 阻断。
- TDD；`ruff` + `mypy --strict` 通过；提交只 `git add` 具体路径。
- 不输出买卖建议 / 评级 / 目标价。

## 三、数据流（按市场路由 + 增量更新）

```
core.entity.market 决定这个实体走哪条链：
  SSE/SZSE (A股, 59家)     → SourceRouter(ANNOUNCEMENTS_CN):  cninfo → wind-docs(降级) → ifind-notice(降级)
  HKEX (港股, 12家)        → hkexnews（单层，官方前端，无需降级：披露易本身就是交易所官方渠道）
  NASDAQ/NYSE + 5家ADR(26家) → edgar（单层，官方 API）
  TSE/KRX (6家，待接)      → edinet / opendart（需你提供 API key，key 未配置时该实体本次跳过，记 warning）
  TWSE 其余7家             → 暂不处理

每日分区（Dagster asset `announcements_daily`）：
  对每个实体，按游标 core.ingest_watermark(source_id=f"announcements:{layer}:{entity_ref}") 取增量区间
    （无游标 = 首次回填，回填起点：A股/港股 2023-09-28 起 3 年；EDGAR 用其 CIK 的 filings 全量，
    SEC 接口本身只返回"最近 1000 条"分页，不需要我们自己截窗口）
  → 写目录行（core.announcement_index）
  → 是否下载 PDF/全文并解析：
       cninfo/hkexnews/edgar 三条主链：entity_ref ∈ download_entities（Task 9 定义的
       `DOWNLOAD_ENTITIES`，D2 目前只有 688041.SH、000977.SZ）→ 下载 + 按 parse_policy 解析；
       否则只建目录、存 url，不下载
       wind-docs/ifind-notice 降级链：从不下载全文（has_full_text=False），全文进待补清单
  → 主链成功：推进游标、resolve 待补
  → 主链失败、降级链成功：写目录，不推进游标（全文还没到），backlog.add
  → 全部失败：本实体跳过，backlog.add，记 failed

巨潮/披露易/EDGAR 恢复后：待补实体区间自动重取，同一公告的降级行被主链行取代
每周（Dagster schedule）：Wind 漏收核对（只读、不写目录，只覆盖 A 股）→ quality 指标 + 告警清单
另起（手动 CLI）：docs parse-pending --entity-ref <ref> --tier <first|second>：把某个实体的
  已存全文（含之前只建目录、后来决定要解析的实体，以及 EDGAR 现有 0 块的文档）解析成块
```

**增量更新的落地方式**：Dagster `DailyPartitionsDefinition` 资产，与既有 `price_normalized` /
`fact_normalized` 同一套模式——每天一个分区，读游标、拉增量、写库、推进游标；同一分区重跑
不产生新数据（`test_rerun_same_partition_fetches_nothing_new`）。EDGAR 和港股接口本身没有
"频率限制/额度"这类需要冷却的失败模式（实测确认，纯 200/403/401），`SourceRouter` 仍然套用
（统一处理路径），但预期这两条链几乎不会触发降级。

CREATE TABLE core.announcement_index (
  index_id       bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  entity_id      text NOT NULL REFERENCES core.entity,
  source         text NOT NULL CHECK (source IN ('cninfo', 'wind', 'ifind', 'hkexnews', 'edgar', 'edinet', 'opendart')),
  source_ref     text NOT NULL,        -- 各源自己的公告/申报 ID
  title          text NOT NULL,
  title_norm     text NOT NULL,        -- 去掉"简称："前缀、NFKC、去空白，跨源比对用

  url            text,
  excerpt        text,                 -- 降级层的摘录 / 片段；有全文的源为空

  valid_from     date NOT NULL,        -- = publish_date
  known_at       timestamptz NOT NULL, -- 精确到秒的源（edgar）直接用；只到日/分钟的源取保守上界

CREATE UNIQUE INDEX announcement_index_live_uk

CREATE VIEW asof.announcement_index AS
SELECT * FROM core.announcement_index
