# 数据底座完善总计划（2026-09-28）

> **最终目标**：做出我们自己的、时点一致、每个数字可溯源的数据层，
> 以一组稳定的**数据接口**交给 Agent 使用。
> **本人不做 Agent**——Agent（07）、评测中的观点评分（08）、合规输出过滤（09）
> 由其他负责人做；本计划只交付他们要调用的数据与接口，并在最早的阶段把接口契约定下来，
> 让他们可以先对着 Mock 开工。
>
> 差距明细见同目录的 `2026-09-28-底座差距与00-06补全计划.md`（逐章审计结果），
> 本文件是在那份清单之上排出的**分阶段执行顺序**。

## 0. 规则

### 0.1 阶段门禁

- 每个阶段有**入口条件**与**出口验收**。出口验收全部通过、并写好验收记录后，
  才能进入下一阶段。"基本完成""代码写完了"都不算通过。
- 验收记录统一写在 `docs/9.28-plan/验收记录/phase-N.md`：执行过的命令、
  原样输出、关键数字、未通过项及处理决定。同时更新 `docs/10-roadmap.md`。
- 某条验收因外部原因（凭证未到、需要自然时长）暂时不能完成时，只允许两种处理：
  ① 停在本阶段等待；② 由负责人书面决定"带条件放行"，写明缺什么、何时补、
  补不上的后果。**不允许悄悄跳过。**
- 创始人手工工作（实体/关系/评测用例录入）不受阶段门禁约束，**从第 0 阶段起并行**，
  它在关键路径上。

### 0.2 贯穿所有阶段的硬约束（来自 CLAUDE.md，不重复展开）

时点一致（查询强制 `as_of`，`known_at` ≠ `ingested_at`，应用层只读 `asof.*`）·
每个数字可溯源 · 计算由代码完成 · 入库同时保留原始响应 · 数据境内存储 ·
密钥只在出网代理层 · TDD · 改切块/检索参数/模型必须跑评测 · 迁移脚本改表 ·
`ruff` + `mypy --strict`。

### 0.3 本计划明确不做

- Agent、工具外壳层、观点生成与评分、通用输出合规过滤器（交给 07/08/09）
- 网页上传、网页编辑口径（ADR-0010 规定诊断界面只读；需要时另立 ADR）
- 自建公告爬虫（CLAUDE.md §4）

### 1B · 数据契约（给 Agent 的接口）

**这一步要最早做**：契约一定，Agent 负责人就能对着 Mock 实现开工，不用等真实数据。

接口以进程内 Python API 为主（业务包内新增只读模块），全部强制 `as_of`、只查 `asof.*`、
**每个返回的数值都带溯源元组**：

| 接口 | 返回 | 溯源 |
|---|---|---|
| `resolve_entity(name, as_of)` | `entity_id` + 置信度，未命中进解析队列 | — |
| `list_entities(node?, as_of)` | 实体清单与环节归属 | `source`（含 `manual:seed` 标记） |
| `get_metric_definition(metric_id, as_of)` | 该时点生效的口径定义 | 版本号 + `known_at` |
| `query_fin_fact(entity_id, metric_id, period?, as_of)` | 数值、单位、币种、期间 | `[metric_id \| source \| known_at]` + `snapshot_id` |
| `query_derived(entity_id, metric_id, kind, as_of)` | 同比/环比/TTM 等标准派生值（代码计算） | 参与计算的每个原始事实的溯源 |
| `get_prices(entity_id, start, end, as_of)` | 日行情 | `[source \| known_at]` |
| `search_blocks(query, as_of, entity_ids?, doc_types?, k)` | 块、页码、bbox、章节、父块 | `[block_id \| page]` |
| `get_block(block_id, as_of)` / `get_document(doc_id, as_of)` | 原文块与文档元数据 | 同上；`can_show_raw=false` 时不返回正文 |
| `get_relations(entity_id, relation_type?, as_of)` | 产业链关系 | `evidence_block` + `source` |
| `match_rules(event_type, trigger_node)` | 传导规则 | `rule_id` + `author` |

通用的 `compute(expr)`、`write_opinion` 属于 Agent 工具外壳层，不在本契约内。

| # | 任务 | 验收 |
|---|---|---|
| 1.8 | 写契约文档（签名、返回结构、错误语义、溯源格式、时点语义），与 Agent 负责人评审定稿 | 双方签字确认的契约文档 |
| 1.9 | 契约的 Mock 实现 + 契约测试（真实实现后续阶段逐个接上，同一套测试） | Mock 通过契约测试；Agent 负责人能直接调用 |

**出口验收**：上表全部单测/集成测试通过；契约文档定稿；`provider_snapshot` 写入路径覆盖率 100%
（用一个扫描测试断言所有真实适配器调用点都经过快照写入）。
