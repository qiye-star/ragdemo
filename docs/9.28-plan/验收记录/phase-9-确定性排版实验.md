执行日期 2026-10-12，分支 p0-foundation。无模型费用、无 token 用量（`--engine deterministic` 不需要模型环境变量）。
前情：[phase-9-解析降本实验.md](./phase-9-解析降本实验.md)（大模型排版版本，页失败率 17.6%–28.7%，剥页眉页脚后无改善）。

> **修复轮 1（Opus 复核后）**：本文 §1–§10 是修复前的数字；复核发现 false-pass 路径（旋转文字数字倒序、数字顺序未校验、页边数据行被剥离）并已修复，

结论：**暂定 NO-GO**（事先写死的 6 条门槛里 4 条未过：`closure_failed = 0`、数字召回、标题召回 / 精确率、非财务表格行召回；
2 条通过：`layout_unsupported` 占比、对文字层的数字精确率）。确定性排版**彻底解决了大模型版本的主要失败（丢字 / 改字）**
——页处理失败从 18%–28% 降到 docs 0 / 131、研究报告 1 / 596，且输出字符可证明全部来自文字层——但它在**结构保真**
（标题、表格、多栏阅读顺序）上不达标，这些问题与"用不用大模型"无关，是版面还原规则本身的上限。详见 §4 与 §6。

## 1. 做了什么

- `parse/local/typeset.py`（纯函数）：字号 / 粗体 → 标题（只在行首加 `#`）；同一文本块相邻行合并为段落（中文字之间不加空格）；
  列表标记原样保留；表格沿用 `find_table_regions + grid_to_markdown` 并按位置插入；多栏页返回 `layout_unsupported`。
- `pipeline.parse_pages_deterministic(pdf_bytes)` / `parse_layouts_deterministic(layouts)`：复用 `strip_decor`、`needs_handback`、`PageResult`；
  最后一步对**自己的输出**做数字闭合 + 字符闭合（双向，即新增和丢失都查）+ 表格原样检查，任一不过记 `closure_failed`（说明排版器有 bug，不重试）。
- `layout.py`：`Word.size` / `Word.bold`（词内字符字号众数、过半字符字体名含 Bold / Black / Heavy 等；用 `extract_words(return_chars=True)`，**不改变分词**，有测试）。
- `compare.py`：`heading_recall_precision`、`heading_level_agreement`、`heading_matches`（标题按"只留字母数字的规范化文本"多重集合匹配，层级另算）。
- `det_report.py` + `scripts/parse_compare.py --engine llm|deterministic`（默认 llm，行为不变）。`report.py` 的 `STATUSES` 没有动
  （既有测试按 4 种状态列数断言），确定性引擎用自己的表头（含 `layout_unsupported`、标题计数、额外数字归类、耗时、`doc_type`）。

### 4.1 数字：本地多出来的数字（对 TextIn 的"精确率"低于 1 的原因）

17 份 accepted 文档合计多出 50 个数字（多重集合差），按位置归类（`classify_extra_numbers`：本页表格行里有 → 表格；落在页顶 / 页底 8% 带 → 页眉页脚；否则其他）：

| 页眉页脚残留 | 表格展开 | 其他 |
|---|---|---|
| 0 | 9 | 41 |

"页眉页脚残留"为 0 是因为分类用的是顶 / 底 8% 带，而这批文档的残留不在带里：41 个"其他"里约 30 个是**抬头行类**（`证券代码：688041 证券简称：…公告编号：2024-001`、年报每页的 `公司代码：688041`，
即 `688041`×15、`2023/2024/2025`、公告编号 `001/002/006/030/033/037`——TextIn 把这些行丢了，文字层里有）。其余约 10 个是表格里的 `减少1.38个百分点` 这类单元格数字（TextIn 把
"减少"与数字拆开 / 改写成符号）与图表里的百分比标签（`49.7%`）。**它们全部在 PDF 文字层里**：输出的数字多重集合是文字层的子集由自检保证，§6.1 独立审计复核。
`strip_decor` 对 < 4 页的文档什么都不剥（任务 2b 的保守设定），所以 2 页公告的首页抬头行一直保留。

### 4.2 数字召回 < 1 的原因（零成本复核，8 份文档）

## 6. 溯源保证与 false-pass 风险

### 6.1 溯源保证（均写成了测试）

- (a) 排版输出的内容字符（`isalnum`）多重集合 == 页面文字层词的内容字符多重集合；数字多重集合同（`tests/parse/local/test_typeset.py`）。
- (b) 排版器输出被改一位数字 / 改一个单位字 / 丢一段文字 / 表格列序对调 → 自检报 `closure_failed`（`tests/parse/local/test_deterministic.py`，4 个用例）。
- (c) 标题行只加 `#`（`test_headings_only_gain_hash_marks`）；(d) 列表标记原样保留（含符号字体私有区圆点）；(e) 多栏页返回 `layout_unsupported`；(f) 表格 markdown 原样出现。
- **独立审计**（已提交为可运行脚本 `scripts/audit_typeset.py`，不经过自检代码）：对排版器 status=ok 的页，输出的内容字符多重集合与文字层词的拼接**逐页比较**；修复前口径下不一致 0 页；
  数字多重集合与文字层比较：不一致 1 页（即 §3 的 `closure_failed` 页，该页在管线里被拦下，不在输出里）。

### 6.2 false-pass 风险（重点）

1. **多栏 / 侧栏页检测很弱，会静默产出"字符齐全但顺序错乱"的 ok 页——闭合校验对阅读顺序完全无能为力。**
   按设计的检测（≥ 30% 的非表格行被同一条纵向空白带分开）只拦下 research 的 3 页、docs 的 5 页。但研报首页普遍是"正文 + 右侧评级 / 行情框 + 图表"，
   实际输出里正文句子与侧栏、图表标签交错（见 §7 抽样：民生 2025-04-24 第 1 页、太平洋 2024-08-19 第 1 页、山西 2026-04-15 第 1 页）。
   这些页状态都是 `ok`，门槛"`layout_unsupported` ≤ 10%"因此是**虚假的通过**。灵敏度测试（只改常量，未改代码入库）：

   | `MULTICOLUMN_ROW_SHARE` | research 被拦页占比 | docs 被拦页占比 |
   |---|---|---|
   | 0.30（设计值） | 0.5%（3 / 596） | 3.8%（5 / 131） |
   | 0.20 | 2.3%（14） | 16.8%（22） |
   | 0.15 | 5.2%（31） | 29.8%（39） |
   | 0.10 | 9.6%（57） | 42.0%（55） |

   单靠调阈值没有干净的工作点：docs 在 0.20 时被拦页就跳到 16.8%，说明有大量并非多栏的页（推测是签章栏、右对齐日期、目录行，未逐页复核）也满足该条件；
而研报首页的侧栏页（如开源 2025-08-07）放宽到 0.15 仍然没有拦下（页内行数多、侧栏行占比低）。
   需要更强的检测（例如按"纵向连续的空白带 + 两侧文字块各自成段"判断，或直接对首页 / 含图页保守降级），这超出了本任务范围，建议作为后续任务。
2. **粗体标题规则在研报上误报严重。** 研报里整行粗体的正文行（要点句、侧栏文字、竖排单字）在页面被侧栏撑乱行距后，满足"整行粗体 + 上下行距大"，被标成 `###`
   （抽样里能看到连续多行 `###` 正文）。docs 的标题精确率 0.71 只反映了公告；研报没有真值，**研报上的标题精确率没有测，肉眼看明显低于公告**。
3. **旋转 / 竖排文字（原描述有误，已更正）**：pdfplumber 会把旋转文字的字序**倒过来**（`12.5` → `5.21`、`2024` → `4202`），而自检的基准（文字层）同样是倒的，
   所以数字 / 字符闭合都发现不了——此前"位置不对但字符不丢"的说法是错的，这类页会以 `ok` 输出**数字被倒序**的文字。修复轮 1 起，含旋转 / `/Rotate` / 文本矩阵从右向左的页一律退回（§11）。
4. **`closure_failed` 的误报**（§3）：自检对数字分词的空白敏感，图表碎片文字会触发；方向安全，但会让个别页退回上层。

## 8. 看到结果之后做过的改动（披露）

第一次跑 docs 之后、正式跑数之前，我改了三处（都在 `typeset.py`，测试先行）：
1. **符号字体圆点（Wingdings / Symbol，pdfminer 抽成私有区字符 `U+F06C`）算列表标记**。原来的正则没有它，导致"圆点开头 + 悬挂缩进"的段落在每个折行处被错误断开（552 的"重要内容提示"三条）。这是 bug 修复。
2. **去掉了"相邻同字号标题行合并成一行"**。设计稿的规则是"每个标题行单独加 `#`"，我最初自作主张做了合并，第一次跑出来标题几乎全匹配不上，退回设计稿的做法。
   这是**回归设计稿**，不是为过门槛调参；合并版第一次跑时多数文档标题匹配为 0（未汇总），拆行版仍有 TextIn 合行的标题匹配不上（§4.3），两版召回都远低于门槛，结论不变。
3. 全角引号 `“”‘’—…·` 与汉字之间不加空格（美观，不影响字符 / 数字）。

没有为了过任何门槛而改校验、改阈值或改指标口径；§6.2 的灵敏度测试只是临时改常量跑出来的，没有入库。

## 10. 后续建议（不在本任务内）

- 把确定性排版作为 L0 的排版步骤本身是可行的：丢字 / 改字问题消失、零成本、秒级以内。要上线必须先补：(1) 更强的多栏 / 侧栏检测（§6.2-1，当前会静默产出顺序错乱的 ok 页）；
  (2) 粗体标题规则在研报上的误报（至少对研报关掉粗体规则）；(3) 标题能力要么接受"只认字号标题"，要么另立一条编号样式规则（上界约 0.80，§4.3）；
  (4) 表格识别（沿用的 `find_table_regions` 是现在 118 / 205 数据行流进段落的主因），这一项与排版方式无关，两个版本都受限。
- 门槛 `closure_failed = 0` 在含图表碎片文字的研报上会被数字分词的空白敏感性击穿；若保留该门槛，需要先让自检对"同一页内仅空白差异"免疫（这会改动闭合校验的定义，需要单独决定）。
