## 这套评测集的局限（必须知道）

1. **合成，不是人工标注**：问题是模型看着答案段落写的，词面会偏向答案，绝对分数偏乐观；它适合做**前后对比**（改切块 / 参数后看数字有没有掉），不适合当"上线达标"的证据。总计划阶段 5 的出口指标仍需要人工标注的 100 条。
2. **只覆盖海光信息 21 份已解析文档 + 浪潮的少量文档**：语料太小（叶子块 474 个），召回数字不代表全量语料下的表现。
3. **gold 是"源块 + 同文块"**：问题也可能被其他块合理回答（如摘要与全文里的同一事实），会被计为未命中，recall 偏保守。
4. **`eval_extraction`、观点评分两套评测集仍为空**：CLAUDE.md §1.4 要求改 prompt / 切块 / 检索参数 / 模型都跑三套评测——目前只有检索这一套有基线。

## 阶段 5 调参记录（2026-09-30，合成评测集 100 条，主库）

**根因：词面一路失效。** `retrieval/lexical.py` 原用 `content @@@ <问题原文>`，语义是合取，问题里只要有一个语料没有的词就命不中。词面单路 recall@10 仅 0.09。改为 `content ||| <问题>`（任一词命中，BM25 打分）后，同一评测集词面单路：

| 分词器（临时还原库上重建索引） | 改前 R@10 / R@50 | 改后 R@10 / R@50 / MRR@10 |
|---|---|---|
| chinese_lindera（主库现用） | 0.09 / 0.23 | 0.80 / 0.92 / 0.524 |
| chinese_compatible | 0.09 / 0.18 | 0.88 / 0.96 / 0.565 |

compatible 略优，但评测集是合成的、偏词面，**暂不换主库分词器**（换需迁移重建索引），待人工标注集复核。

**混合检索（修复后）：**

**5.6 Chroma vs pgvector**（修词面前测，w 0.3/0.7）：R@10/R@50 完全相同（0.76/0.84），MRR 0.601 vs 0.613，p95 2.6s vs 4.4s → 无收益，向量召回保持 pgvector，Chroma 仅保留为可选候选生成器。
