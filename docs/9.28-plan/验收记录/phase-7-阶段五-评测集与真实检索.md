- **100 条检索评测集（合成）**：`ragdemo eval generate`（`evals/generate.py`）。流程：`evals.sampler` 分层抽样选块（固定种子可复现）→ 过滤模板句 / 勾选项 / 过短块 → 同实体内**正文完全相同的块并列为 gold**（跨期重复的固定表述，只标一个会把"找对了另一份"判成错）→ DeepSeek 写一个问题（按目标难度分三种写法）→ 拦截买卖 / 评级字样、指代不明（"这份""该公司"）、近似原文照抄、重复问题 → 入库。
  - **作者标记 `auto:deepseek-chat:v1`**，`notes` 记录生成参数、目标难度、词面重合度、源块 id——合成集与人工标注集始终可区分，可随时 `--replace-auto` 整批重生成或剔除。
  - 100 条：50 条带实体过滤；gold 平均 1.13 个块（最多 5）；来源文档类型 announcement 85 / annual_report 14 / quarterly 1（库里巨潮文档的 `doc_type` 大多标为 announcement）。

## 基线（真实 bge-m3 + bge-reranker，切块 v2，2026-09-30）

| 指标 | 数值 |

按难度：easy 0.75（4 条）/ medium 0.69（29 条）/ hard 0.78（67 条）。**难度标签不可信**：它按问题与原文的字二元组重合度回填，而问题里带着公司名和期别，重合度整体偏低，导致 67% 被标成 hard，hard 反而高于 medium。标签只在合成集内部粗略分档，不要据此下结论。

## 这套评测集的局限（必须知道）

1. **合成，不是人工标注**：问题是模型看着答案段落写的，词面会偏向答案，绝对分数偏乐观；它适合做**前后对比**（改切块 / 参数后看数字有没有掉），不适合当"上线达标"的证据。总计划阶段 5 的出口指标仍需要人工标注的 100 条。
2. **只覆盖海光信息 21 份已解析文档 + 浪潮的少量文档**：语料太小（叶子块 474 个），召回数字不代表全量语料下的表现。
3. **gold 是"源块 + 同文块"**：问题也可能被其他块合理回答（如摘要与全文里的同一事实），会被计为未命中，recall 偏保守。
4. **`eval_extraction`、观点评分两套评测集仍为空**：CLAUDE.md §1.4 要求改 prompt / 切块 / 检索参数 / 模型都跑三套评测——目前只有检索这一套有基线。

## 与切块 v2 的关系

阶段三修质量门禁时改了切块算法（v2，合并同小节同页的短段落），当时评测集为空、无法按 §1.4 验证。现在有了合成基线，**v2 是这套基线的被测对象**；若要严谨对比 v1 vs v2，需要在 v1 参数下（`ChunkConfig(merge_short_paragraphs=False)`）重切并重新生成 / 迁移 gold 后各跑一次——尚未做，待有人工标注集时一并做。
