# 术语表

按主题分组。术语首次在其他文档中出现时应链接回本页。

## 时点相关

**as_of / 时点** — 查询或分析所假设的「当前时刻」。在该时点下，系统只能看到
`known_at <= as_of` 且尚未被取代的数据。类型必须是带时区的 `timestamptz`，
且**没有默认值**。见 `03-point-in-time.md` §2。

**known_at** — 该数据在**现实世界中最早可被获知的时刻**。它是数据自身的属性，
与本系统何时接入无关。回填十年历史数据时，每行的 `known_at` 应是它当年真实的
披露时刻。**不是入库时间**——这是对原简报表述的修正，见 `03-point-in-time.md` §1.2。

**valid_from** — 数据所描述的期间起点。三季报的 `valid_from` 是 7 月 1 日，
`known_at` 是 10 月底的公告时刻。

**superseded_at** — 该行被更正版本取代的时刻；`NULL` 表示当前有效。
更正是追加新行 + 给旧行打此标记，不是原地修改。

**publish_at** — 文档或事件在现实中被公开发布的时刻。绝大多数情况下等于
`known_at`，两者分开是为了表达供应商的获知延迟。

**ingested_at** — 本系统把数据写入数据库的时刻。**只用于运维排查，
禁止出现在任何 `as_of` 过滤表达式中。**

**双时间轴 / bitemporal** — 同时记录「数据描述的时间」与「数据被知道的时间」
两条时间轴的建模方式。它让「还原任意历史时点的认知状态」成为可能。

**前视偏差 / look-ahead bias** — 回测中使用了当时尚不可知的信息，
导致结果系统性高估。本系统的全部时点机制都是为了消除它。

**双跑一致性** — 相隔一段时间、用同一个 `as_of` 跑两次，结果必须完全一致。
这是检验时点机制是否真的生效的端到端测试。见 `03-point-in-time.md` §5.1。

## 文档与检索

**块 / block** — 文档切分后的最小检索单元，对应 `core.doc_block` 一行。

**父子块** — 检索与生成对块长度要求相反的解法：子块 ≤ 200 字用于召回
（信号集中），父块为整个小节用于生成（上下文完整）。见 `05-document-pipeline.md` §4。

**叶子块 / is_leaf** — 可被召回的块。注意表格块既是父块也是叶子块，
因此不能用「有没有父块」判断，必须用显式的 `is_leaf` 列。

**content_desc** — 表格或图的一句自然语言描述。纯数字表格的向量表示很弱，
描述句是它被语义检索命中的主要途径。

**BM25** — 基于词频与文档长度的经典相关性打分算法。本系统用 ParadeDB 的
`pg_search`（tantivy 内核）实现真 BM25，而非 PostgreSQL 内置的 `ts_rank`。
见 [adr/0001](adr/0001-bm25-paradedb-pg-search.md)。

**HNSW** — 向量近似最近邻索引。近似意味着它可能漏掉真正最相似的向量，
与过滤条件组合时尤其明显——这是 `06-retrieval.md` §3 处理的核心问题。

**RRF / Reciprocal Rank Fusion** — 多路召回结果的融合方法，用排名而非分数：
`score(d) = Σ w_i / (k + rank_i(d))`。因为只用排名，不受各路分数尺度差异影响。
本系统用加权 RRF（默认 BM25 0.6 / 向量 0.4，k=60），这是对原简报
「加权 + RRF 并存」表述的统一，见 `06-retrieval.md` §4.1。

**重排 / rerank** — 用交叉编码器对召回结果重新打分。比双塔嵌入精确得多，
但慢，因此只用于融合后的前 50 条。

**下推 / pushdown** — 把过滤条件送进索引内部执行，而不是取出候选后再过滤。
时点过滤能否下推，直接决定历史时点的召回率。

## 产业链与知识

**L1 / L2 / L3** — 产业链的三级划分。L1 为大层（算力、模型、应用……），
L3 为最细的环节，是传导规则与观点评分基准的作用单位。

**传导规则 / propagation_rule** — 某环节的某类事件对其他环节影响的方向、时滞与机制。
`mechanism` 字段必填：没有机制说明的规则不能进入输出。

**产业链映射** — 给定一个事件，算出受影响的实体清单及其权重。
权重由代码按 `ai_revenue_pct × share_estimate` 计算，模型不参与。

**AI 收入占比 / ai_revenue_pct** — 实体收入中可归为 AI 相关的比例。
它作为 `fin_fact` 中的一个指标存储（因而具备时点语义），
`core.entity` 上的同名列只是当前值的展示缓存，**禁止进入计算**。

**别名消歧** — 把文本中的公司指称映射到唯一 `entity_id`。三层降级：
代码精确匹配 → 别名精确匹配 → 上下文打分。三层都不确定则进人工队列，**不猜**。

## Agent 与输出

**观点 / opinion** — Agent 生成的带依据链与置信度的判断，绑定生成时的 `as_of`。
未经人工确认（`confirmed_by IS NULL`）的观点不得对外输出。

**Claim** — 输出中的一条论断，必须携带 `citations` 或被标记 `is_inferred`。

**外壳层 / ToolShell** — 包裹外部工具与数据访问的自有层，做参数校验、权限注入、
预算控制、缓存、审计。Agent 只能通过它访问数据，这条约束由模块依赖规则强制。

**验证器** — 输出离开系统前的后置检查，6 项，以代码为主。其中
「引用的 `known_at <= opinion.as_of`」同时是合规与时点的交叉防线。

**unresolved** — 多空辩论中未能证实也未能证伪的关键分歧。它进入简报的「待跟踪」
小节，也是下一轮数据采购的需求来源。

**档位 / model tier** — 小 / 中 / 强三档模型。代码中只出现档位名，
具体模型在配置文件中绑定，便于整体切换。

## 评测与评分

**价格分** — 观点评分的一轨：目标实体相对其 L3 环节等权组合的超额收益，
按 ±3% / ±8% 分五档。全自动，由代码计算。

**论据分** — 观点评分的另一轨：后续披露的事实是否印证原论据。人工判定，
Agent 只做预标注。与价格分**分开存、分开报、不加权合并**。
见 [adr/0007](adr/0007-opinion-scoring-dual-track.md)。

**超额收益 / α** — 个股收益减去基准收益。基准是该实体在 `opinion.as_of` 时点
所属 L3 环节的等权组合，成分清单快照在 `opinion_score.benchmark_def` 中以保证可复现。

**反向率** — 得负分的观点占比。比命中率更值得盯，因为「判断反了」的成本
远高于「判断中性」。

**recall@10 / MRR** — 检索评测指标。`recall@50` 与 `recall@10` 的差距用于定位问题：
差距大说明重排不好，两者都低说明召回不好。

**幻觉率 / hallucination_rate** — 抽出了文档中不存在的值的比例。阈值是 **0**，
不是「尽量低」。

## 工程

**适配器 / Adapter** — 外部数据源的统一接口。业务代码只 import 协议，
不 import 任何供应商 SDK。`known_at()` 是适配器的方法，因为只有它知道原始字段的语义。

**契约测试** — 针对适配器接口行为的测试（幂等、时区、顺序连续性等），
对 Mock 与真实实现都要通过。

**录制回放测试** — 用录制的真实供应商响应回放的测试。供应商格式变更时它会红，
是发现上游变化的主要手段。

**幂等** — 同一输入重跑产生同一结果。Dagster 的每个资产必须幂等，
否则回填会产生重复或不一致的数据。

**增量触发** — 只有新数据进入才触发相关 Agent，不做每日全量重算。
这既是预算约束也是架构原则。

**背压** — 事件队列积压时的降级策略：暂停最贵的辩论环节，只跑入库，
待队列回落后补跑。降级而非丢弃。

**哈希链** — `audit.tool_call_log` 每行的哈希包含前一行的哈希，形成单向链。
它防的是无声的篡改，不是有权限者的篡改。
