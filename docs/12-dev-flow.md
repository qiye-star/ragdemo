# 12 · 主线开发流程：00→09 串联、验收标准与当前进度

这份文档把 `00`–`09` 十份规范文档串成**一条可以从头走到尾的开发主线**，
每个环节回答四件事：**由哪份文档治理**、**对应哪些工作流任务**、
**验收标准是什么**、**现在做到哪一步**。

> **为什么需要这一份。** `10` 按「阶段」切（P0–P6，回答*交付什么*），
> `11` 按「工作流」切（W0–W9，回答*怎么交付*）。两种切法都对，但都不是
> 新人第一次动手时想要的那条线——他想知道的是「我该从哪份文档开始读，
> 读完做什么，做完怎么算数」。这份文档提供那条线。

## 1. 主线：为什么是这个顺序

```
  ① 边界          ② 骨架                      ③ 地基
  00-overview ──► 01-architecture ──► 02-data-model ──► 03-point-in-time
  目标/非目标      分层/部署/依赖方向    DDL/数据字典      三时间戳/as_of/防泄漏
  合规底线                                                      │
                                                                │ 所有下游都压在它上面
                          ┌─────────────────────────────────────┤
                          ▼                                     ▼
  ④ 进数据                                          ⑤ 变成可检索的块
  04-ingestion ─────────────────────────────────► 05-document-pipeline
  适配器/Dagster/known_at 计算                      解析/切块/父子块/嵌入
                          │                                     │
                          └──────────────┬──────────────────────┘
                                         ▼
                                 ⑥ 06-retrieval
                                 过滤→双路召回→RRF→重排→父子块展开
                                         │
                                         ▼
                                 ⑦ 07-agents
                                 工具外壳层/编排/验证器/输出模板
                                         │
                  ┌──────────────────────┴──────────────────────┐
                  ▼                                             ▼
          ⑧ 08-evaluation                            ⑨ 09-compliance-security
          三套评测集/观点评分/CI 门禁                  合规过滤/权限/审计哈希链
```

**这个顺序不是偏好，是硬依赖**，三处不能调换：

1. **`03` 必须在 `02` 之后、`04` 之前。** 时点语义决定了每张表长什么样
   （三个时间戳）、每个查询怎么写（`as_of` 强制），接入侧算 `known_at` 时
   已经没有商量余地。倒过来做就是把错数据写进按设计不可删的历史库
   （[03](03-point-in-time.md) §3.2）。
2. **`05` 必须在 `04` 之后。** 文档管线的输入是接入层产出的 `NormalizedDocument`。
3. **`08` 必须在 `06` 之后但不能拖到最后。** 评测集是改切块参数、检索权重、
   prompt 的唯一依据（`CLAUDE.md` §1.4）。没有它，后面每一次调参都是盲调。

**唯一能真正并行的是 W9（创始人手工工作流）**——种子数据、供应商评估、
评测集标注。它零代码依赖却在关键路径上，必须第 1 天启动
（[11](11-sdlc.md) §3 W9）。
