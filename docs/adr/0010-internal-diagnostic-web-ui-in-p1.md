# ADR-0010 · 内部诊断 Web 界面提前到 P1，面向用户的产品前端仍在 P4

- 状态：已接受
- 日期：2026-09-22
- 决策者：创始团队
- 影响：ADR-0006（P1–P3 不做 Web 前端）—— 收窄其适用范围，不取代

## 背景

文档管线（W2.1–W2.5）与检索（W3.1–W3.7）在代码层面已经完成并评审过，
但库里 `core.document` 一行都没有——两条链路从未指向过一份真实文档。

这个状态下「切块对不对」没有任何人能回答。CLI 能打印块，但判断切块边界
需要同时看章节树、页码、表格完整性与相邻块的重叠，那是二维的，终端一次
只能打印一维。检索诊断同理：要判断融合排名合不合理，需要同一查询下
20 行 × 6 列并排比较 BM25 排名、向量排名与最终排名，重复几十次——这也不是
终端输出能承载的东西。

这触到了一条已锁定的决策：`CLAUDE.md` §2 把「前端」列为 P1–P3 不做
（ADR-0006），变更需要新增一篇 ADR 并说明推翻条件。本 ADR 就是那份说明。

**如实说明：ADR-0006 的三条推翻条件一条都没有触发。**

- 「标注效率被证明是进度瓶颈（评测集录入耗时超过对应阶段总工时的 20%）」——
  `evals/` 目前只有 `.gitkeep`，W9.3（检索评测集 100 条标注）尚未开始，
  标注成本是 **0**，不是 20%；
- 「出现需要早期用户反馈的商业机会」——没有出现；
- 「技术负责人到位且有前端能力富余」——技术负责人仍待招。

真实理由是上面两段：切块与检索的正确性今天没有任何人能判断，
且这不是「标注效率」问题，而是「终端只能打印一维、问题是二维的」这一更基础的
限制。retrofit 一个没触发的推翻条件比直说更糟，所以本 ADR 不假装
ADR-0006 的条件成立。

## 备选方案

**A. 维持 ADR-0006，用 CLI 打印切块结果**（`ragdemo parse inspect --doc-id`）
不新增前端，靠更详细的 CLI 输出回答「切块对不对」。

**B. 把 P4 的 Web 简报整体提前**，即取代 ADR-0006
不再区分内部诊断与产品前端，直接把 P4 的面向用户界面提前到 P1。

**C. 只做只读的内部诊断界面**
产品级体验但只读无账号：按正式 B 端产品标准做 UI，但后端只读、仅内网、
无账号、硬编码只看公共检索空间。账号 / 私有上传 / 对外暴露仍留 P4。

## 决策

**选 C。**

**为什么不是 A**：要判断的东西是二维的——块边界 × 页码 × 章节树 × 四段检索
排名——终端一次只能打印一维。检索诊断需要同一查询下 20 行 × 6 列并排比较，
重复几十次。A 不是错的，只是答不了这个问题：它能打印数据，但没法让人
在一屏内同时看见结构、位置与排名的相互关系。

**为什么不是 B**：P4 验收里最重的两条是「20 位种子用户可登录」与
「越权测试 0 命中」（`10-roadmap.md` P4），它们要求 W8.5 账号体系与
W5.4 RLS 策略，两者都不存在。把 B 提前等于把 P4 最难的那条验收
（私有材料泄漏）静默搬进 P1，而 `10-roadmap.md` 的阶段划分正是防这件事的东西。

## 边界

**解开**（P1 起可做）：

- `api/`（`packages/ragdemo/src/ragdemo/api/`）现在可以写代码——FastAPI，
  **只有 GET，没有任何写接口**；
- `web/` 可以放诊断界面的静态资源；
- 服务只绑回环 / 内网，与 `01-architecture.md` §4 的 `dagster-webserver`
  同一网络姿态（内网 / VPN 访问，不对公网开放）。

**没有解开**（仍属 P4，本 ADR 不触碰）：

- 面向用户的简报阅读与追问（W8.2）；
- 账号体系、登录、会话（W8.5）；
- 用户上传 → 私有空间（W8.3）——**`TEXTIN_ALLOW_PRIVATE` 不因本 ADR 打开**；
- Excel 导出（W8.4）；
- 任何对公网暴露的端口。

**立刻生效的提前继承约束**（不是提前豁免，是把 P4 的出口条件提前拿来用）：

- 所有接口强制 `as_of` 参数，无默认值（`CLAUDE.md` §1.1，也是 W8.1 原出口
  条件的一部分）；
- 只查 `asof` schema 的安全视图，不查 `core.*` 基表；
- `owner_user IS NOT NULL` 的块硬编码不可见，不由请求参数控制；
- 界面不生成任何论断文案，只展示原文块与排名数字——不做判断，只做展示。

## 后果

1. ADR-0006 后果 3（`src/api/` 在 P4 才开始写）被推翻，但 W8.1 的出口条件
   （强制 `as_of`、权限上下文隔离）被提前继承，诊断界面不是「先随便做一个」
   的借口。
2. 多了一个会被误当成产品的东西。内部工具一旦好用就会被拿给外人看。
   对策：页面顶部固定「内部诊断工具，非产品界面」标识。
3. P4 不缩水：本 ADR 从 P4 拿走的只有「有一个 FastAPI 进程存在」这一件事，
   P4 的六条验收一条不减。W8.1 拆成 **W8.1a**（P1，内部只读）与
   **W8.1b**（P4，对外 + `SET LOCAL` 权限上下文），见 `11-sdlc.md` W8。
4. 技术栈必须是能扔掉的：没有技术负责人，维护成本要接近 0。**不引入
   Node 构建链**；引入 npm 是独立决定，另写 ADR。这也接上 ADR-0006
   后果 4（HTML 模板是 P4 页面的起点）。
5. 它立刻暴露一个真问题：库里没有任何 `core.document` 行，界面第一次打开
   是空的。因此本 ADR 与首批真实文档入库是同一件事的两半——单独做任何一半
   都没有意义。
6. `evals/cli.py` 头部的「CLI 而非 Web」不再全对——**标注入口仍是 CLI**，
   本 ADR 没有解开标注界面，`ragdemo eval add-retrieval` 等命令的地位不变。

## 推翻条件

- 界面出现任何写操作（人工确认观点、录评测集、编辑块）→ 它已不是诊断工具，
  必须补齐权限、审计与 `SET LOCAL` 权限上下文，回到 W8.1b 的完整出口条件；
- 被要求给团队之外的任何人使用（哪怕一位种子用户）→ 立刻停用，直到 P4 的
  账号体系与越权测试完成；
- 维护它的时间超过对应阶段总工时的 10% → 说明它不是「扔得掉」的，砍掉退回
  CLI（方案 A）；
- P4 的 Web 简报开工时它已成为技术债 → 应该重写而不是让它长大。
