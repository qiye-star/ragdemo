# ADR-0001 · 中文全文检索用 ParadeDB `pg_search`

- 状态：已接受
- 日期：2026-09-21
- 决策者：创始团队

## 背景

混合检索需要一路词法检索（BM25）与一路向量检索。语料主体是中文上市公司公告与研报，
包含大量专有名词（CoWoS、HBM3E、先进封装、算力租赁）——这类词的精确匹配正是
向量检索的弱项，BM25 一路不可省。

PostgreSQL 内置的全文检索有两个问题：它需要额外的中文分词扩展（`zhparser` / `pg_jieba`），
而且 `ts_rank` / `ts_rank_cd` **不是 BM25**——它没有文档长度归一化，
对长短悬殊的块（本系统的块从 200 字到整张表格都有）排序质量明显劣于 BM25。

## 备选方案

**A. PostgreSQL 内置全文 + `zhparser`**
云厂商托管 RDS 普遍支持，运维最省，与向量同库同事务。
代价：打分不是 BM25；`zhparser`（SCWS 内核）的词典更新不便。

**B. ParadeDB `pg_search`**
tantivy（Rust 版 Lucene）内核，真 BM25，自带中文分词器，作为 PostgreSQL 扩展运行，
因此仍然与向量、事实表同库同事务。
代价：托管 RDS 不允许安装第三方扩展，必须自建数据库。

**C. 外置索引（Elasticsearch / Meilisearch / 独立 tantivy 服务）**
检索能力最强、可调优空间最大。
代价：引入第二套存储，必须自己维护与 PostgreSQL 的同步与**时点一致性**——
而时点一致性恰恰是本系统最不能出错的地方。跨存储的 `known_at <= as_of` 过滤
无法在一个事务内完成，双写失败时会产生「检索得到但查库查不到」的幽灵证据。

## 决策

**选 B。**

决定性理由是时点一致性：`03-point-in-time.md` 的全部机制
（`asof` schema 安全视图、会话 GUC、列级权限）都建立在「一次查询、一个事务、
一套过滤」之上。方案 C 会把这套机制撕成两半，而方案 A 的打分质量不足以支撑
「先过滤后检索」场景下本就偏小的候选集。

`pg_search` 的另一个关键优势在 `06-retrieval.md` §3.2：把 `entity_id`、`known_at`
等列作为 `fast` 字段放进索引，过滤在 tantivy 内部完成，
这是时点过滤后仍能保证召回的关键手段。

## 后果

1. **数据库必须自建**，不能用阿里云/腾讯云托管 RDS → 见 [ADR-0002](0002-self-hosted-paradedb-single-db.md)。
   备份、监控、高可用全部自理。
2. **镜像版本必须固定**。`pg_search` 的索引 DDL 选项（`text_fields` 的 JSON 结构、
   分词器名称、`key_field` 支持的类型）在版本间变动过。
   `02-data-model.md` §5.5 的语法以 P0 实测为准。
3. **主键类型受约束**。`key_field` 对整数类型支持最稳，因此
   `block_id` 定为 `bigint`（`02-data-model.md` §1.2）。
4. **中文分词器需要实测选型**。`chinese_lindera`（词典分词，精度高）与
   `chinese_compatible`（按字切分，召回高）在评测集上对比后决定，
   这是 P1 的一项任务（`10-roadmap.md`）。

## 风险

**许可证**：`pg_search` 采用 AGPL-3.0。自建自用不构成分发，风险低；
但 P6 向机构客户交付私有化部署时，需要完成许可证审查——AGPL 的网络条款
与「把扩展随产品一起交付」的组合需要法律意见。

缓解：私有化交付前完成书面审查（`10-roadmap.md` P6 验收项）。
若结论是不可接受，退路是「机构版换用方案 A，公有云版保留方案 B」——
因为两者都在 PostgreSQL 内，切换只影响 `06-retrieval.md` 的 BM25 一路 SQL，
不触及数据模型与时点机制。这个退路的存在让本决策的风险可控。

## 推翻条件

出现以下任一情形，重新评估：

- 许可证审查结论为机构交付不可接受，且公有云/机构双版本维护成本过高；
- 评测显示 `pg_search` 相对方案 A 的 `recall@10` 提升 < 2 个百分点
  （即真 BM25 的收益不值自建数据库的运维成本）；
- 托管 RDS 开始支持 `pg_search`（则可回到托管，本决策的主要代价消失）；
- 语料规模超过单机 PostgreSQL 的合理承载（约千万级块），需要分布式检索。
