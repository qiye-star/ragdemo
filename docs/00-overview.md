# 00 · 总览与边界

## 1. 目标

构建一个面向中国大陆 AI 产业链上市公司（含关键海外环节）的研究引擎：

```
多数据源接入 → 时点一致的数据库 → 带溯源的检索 → 多 Agent 生成研究观点 → 观点评分与回测
```

产出物是**研究参考**，不是投资建议。

## 2. 引擎要回答的问题

引擎的价值不在「能搜到公告」，而在这四类问题上——它们都要求时点一致与可溯源，
这正是通用 RAG 做不到的地方：

1. **时点还原**：「2024-08-01 那天，我能知道的关于寒武纪的事实是什么？」
   → 要求物理上看不到当时尚未披露的数据，包括后来被更正的版本。
2. **产业链传导**：「台积电 CoWoS 扩产 30%，哪些 A 股环节受影响、方向如何、时滞多久？」
   → 要求实体关系图 + 传导规则 + 按 AI 收入占比与份额加权。
3. **可审计的判断**：「这个看多观点的依据是什么？每个数字出自哪一页？」
   → 要求生成链路上每个事实都绑定来源。
4. **事后复盘**：「过去三个月，引擎产出的观点准确率是多少？」
   → 要求观点入库时锁定 `as_of`，评分时用代码计算而非模型自评。

## 3. 团队与约束

| 项 | 内容 |
|---|---|
| 团队 | 2–3 位金融背景创始人（规则、图谱、标注）；技术负责人 1 人（待招，前期外包过渡）；数据工程师 0–1 人 |
| 语言与运行时 | Python 3.11+ |
| 数据库 | 自建 ParadeDB（PostgreSQL 15+ / `pg_search` / `pgvector`），见 [adr/0002](adr/0002-self-hosted-paradedb-single-db.md) |
| 编排 | Dagster（数据管线）+ LangGraph（Agent 流程） |
| 模型 | 国内可备案模型 API（DeepSeek / Qwen / Kimi） |
| 嵌入 / 重排 | `bge-m3`（或 Qwen3-Embedding）1024 维 / `bge-reranker-v2-m3`，托管 API，见 [adr/0004](adr/0004-hosted-embedding-reranker-api-1024d.md) |
| 部署 | 云主机 + docker-compose 全栈；P1 起即为可私有化架构 |
| 预算 | 数据 + 模型每月 ≤ 5000 元（起步期） |

**预算的工程含义**：不能有常驻 GPU；不能做每日全量重嵌入；不能让 Agent 无节制调用大模型。
这三条直接约束了「增量触发」原则（`CLAUDE.md` §1.6）、嵌入缓存策略
（`05-document-pipeline.md` §5）与工具外壳层的预算控制（`07-agents.md` §4）。

## 4. 合规硬约束

这些不是「尽量做到」，是**产品能否存在**的前提：

| 约束 | 实现位置 |
|---|---|
| 不输出买卖建议 / 目标价 / 评级 / 仓位 | 输出合规过滤器，`09-compliance-security.md` §1 |

## 5. 非目标

写清楚不做什么，与写清楚做什么同等重要。以下内容**不在范围内**，出现相关需求时先讨论边界：

- **不自研模型**——包括不做预训练、不做全参数微调。必要时只做 prompt 工程与少量 LoRA 评估。
- **不自建爬虫**——A 股 / 港股公告走供应商结构化接口。例外：公司 IR 页（台积电月营收、法说会）与政策官网在 P2/P3 做定向抓取，受 `robots.txt` 与频率限制约束。
- **不做行情终端**——不提供实时行情、不做 K 线图、不做盘中推送。行情数据只用于观点评分的事后计算。
- **不做全行业覆盖**——只覆盖 AI 产业链。实体表起步 100 家，靠 `l1_layer` / `l2_segment` / `l3_node` 三级产业链标签界定边界。
- **P4 之前不做 Web 前端**——见 [adr/0006](adr/0006-no-frontend-until-p4.md)。

## 6. 成功标准

分阶段的量化验收见 `10-roadmap.md`。整体上，引擎做成了的标志是：

1. 任意 `as_of` 时点的查询可复现——同样的问题、同样的时点，今天和三个月后跑出同样的证据集。
2. 检索 `recall@10 > 0.80`，字段抽取准确率 `> 0.95`。
3. 连续两周每日自动产出事件解读与观点，且观点 100% 带完整依据链。
4. 观点库积累三个月评分，价格分与论据分都有可公开的数字。
