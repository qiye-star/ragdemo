## 成本

- 全部交给 TextIn：积压约 970 元（公告去重后 874 + 研报 81），**混合成本 = 0.1356 元/页**。
- L1 表格页通过率按实测为 0（上界 0.09），要达到 0.05 元/页，在 L0 关闭时需要 L1 通过率约 0.78。**0.05 目标在现有引擎下不可达**（停止条件 S1、S2 触发：L1 通过率 < 0.4）。
- L1 不再投入调优（停止条件 S2），除非用户提供 GPU 或更大内存的机器、或改用带单元格坐标的引擎输出并设计逐格校验（本记录不评估）。

## 对 v8 校验口径的说明（重要，避免误读）

L1 的失败主要来自 v8 校验对 markdown 的零容忍规则（顺序必须与文字层一致；表格不得含空单元格、合并单元格、不规则行）。这些规则是为"纯文字页"设计的，对表格页偏严，放宽会削弱"数字不被放到错误单元格"的保证。表格页应当使用**逐单元格校验**（需引擎给出单元格坐标），而现有 L1 适配器输出不含坐标——这是 L1 在表格页上不可用的结构性原因，不只是识别质量。

## 可选的降本路径（需用户决定）

1. **全部走 TextIn**：积压约 970 元，一次性；今后增量按 0.1356 元/页。简单、已验证、逐页审计已有。
2. **启用第二版 L0 处理纯文字页**（需用户批准放宽 G6a，或做第三版）：纯文字页约占路由范围 53%（census 上界），可省约三成页费；溯源硬线全部通过。
3. **减少送解析的页数**（与引擎无关）：研报跳过免责声明与末尾附页、只解析需要的页、依赖去重与解析缓存（旧计划 NO-GO 退路）；23 份已取代的重复副本不再解析。
4. 以上可叠加（2 + 3）。
