# 逐页验收定义（P1–P8，已实现）

来源：`docs/10.12-plan/验收路线与风险评估.md` §1.3，控制者裁决 U-D1 采纳。
实现：`packages/ragdemo/src/ragdemo/parse/acceptance.py`（纯函数）；测试：`tests/parse/test_acceptance.py`（29 例）。
原文有歧义处一律取保守读法（宁可误报，绝不漏报），选择记在模块 docstring。

## 1. 页级与文档级检查

| 编号 | 检查（实现口径） | 不过时 |
|---|---|---|
| P1 | 层级 ∈ L0–L3、PageKind 与引擎标识非空、页码 ≥ 1；L1/L2/L3 必须至少一条选路/降级原因（L0 可无）。文档级并入：页码无重复、无缺页（需 `page_count`）、`forced_l3` 的文档每页必须是 L3 | 文档 rejected |
| P2 | L0/L1 须有文字层且 `tier_verdict=passed`；L2 须 `passed`；`failed` 与 `not_run` 都算未过（失败页应已降级）；L3 记通过并注明「事后审计见 P3」 | 文档 rejected |
| P3 | 入库正文（去 HTML 标签/注释/实体）数字多重集合 ⊆ 文字层数字多重集合；多出个数 = `unverified_numbers`。无文字层页 `state=unverifiable_scan`、`passed=False`（不是通过）。**含 TextIn 页** | 见 §2 |
| P4 | 文字层内容字符 ≥ 40 的页：入库内容字符 / 文字层内容字符 ≥ 阈值。**阈值不预填**，传 `None` 时 `state=not_evaluated`（不算通过，文档层一条告警）。图表剥离文字仅在本页有图表区域且有 figure 时才从分母扣除 | 仅告警 |
| P5 | `page_kind ∈ {table, financial_statement}` 的页 `table_blocks ≥ 1` | 文档 rejected |
| P6 | 检出图表区域的页：figure 数 ≥ 区域数，且每个 figure 有 `bbox`、64 位十六进制 `png_sha256`、`caption` 或 `source_note`、`can_show_raw` 非空 | 仅告警 |
| P7 | 文档级：`provider_snapshot` 已存、`parse_engine` 非空、`known_at` 未改、私有材料不在公共空间。元数据缺失按失败 | 文档 rejected |
| P8 | 文档结论，见 §2 | — |

## 2. 六种文档结论（`DocVerdict.state`）

优先级从高到低：

| 状态 | 条件 |
|---|---|
| `empty_document` | 零页（即使元数据声称有页，也按零页处理） |
| `rejected` | 任一页 P1/P2/P5 未过，或 P7 未过，或缺页/重复页，或 `forced_l3` 文档含非 L3 页 |
| `textin_unverified` | 无 rejected 条件，但 **L3/TextIn 页**有数字不在文字层（停止条件 S5 专用，独立状态，绝不落入 accepted） |
| `partially_accepted`（部分合格） | 无以上条件，但非 TextIn 页有未溯源数字（L0/L1 校验通过却审计失败，说明校验与审计不一致，需排查） |
| `accepted_with_scan` | 一切通过，仅有无文字层页无法核对数字 |
| `accepted` | `unverified_numbers = 0`、无扫描页、P1/P2/P5/P7 全过 |

`DocVerdict` 另带 `reasons`、`warnings`（P4/P6/页数未提供/阈值未配置）、`unverified_numbers`、`scan_pages`。
告警不改变结论，但调用方应记录。

说明：原文只列出 accepted / accepted_with_scan / rejected 与 P3 行的「部分合格」，本实现把 TextIn 数字审计失败与零页各自拆成显式状态，共六种；`partially_accepted` 即「部分合格」。

## 3. 输入来自哪里

| 输入 | 来源 |
|---|---|
| `tier` / `engine` / `reasons` | `PageRoute`（`parse/tiered/types.py`），旁路 JSON 或 `core.parse_page_route` |
| `page_kind` | v2 `classify_page`（T5）；未落地前由调用方给字符串 |
| `tier_verdict` | 产出该页的层：L0 = 闭合 + 顺序检查，L1 = `verify_against_text_layer`，L2 = `verify_dual`；L3 传 `not_run` |
| `text_layer_text` | pdfplumber 取的该页文字层（`parse/tiered/pdfpages.py`）；无文字层为 `None` |
| `output_markdown` | 该页入库块正文；**不得含 figure 元数据**（sha256 内含数字）。表格块用 HTML 或管道表均可 |
| `stripped_text` / `chart_regions` / `figures` | v2 图表检测与裁图（`parse/local/chart.py`、figure 块） |
| `table_blocks` | 该页入库的 `table` 块数 |
| `DocumentMeta` | 文档表与 `provider_snapshot`；`forced_l3` 由 W3 的标题/文件名识别提供（本任务只收标志） |
| `coverage_threshold` | 先在已解析文档上测 P4 比值分布再定（当前无值） |

## 4. 仍需人工（不可能逐份自动）

- 阅读顺序（G9 口径）抽样。
- 表格数字的标签/单位/行列归属：多重集合校验对「同行跨列互换」无能为力。
- 图表检出质量（U5）。
- 无文字层页的 OCR 正确性（无参照，只能抽查）。
- 建议常设「每月抽 30 个数字 + 15 页阅读顺序」。

## 5. 已知局限

- P3 只验「入库数字 ⊆ 文字层数字」，不验反向（漏数字归 P4 粗略覆盖）。
- 文字层本身错误（乱码、错误编码）时 P3 也会通过。
- 数字抽取沿用 `number_closure`，字母后的 `-` 可能误当负号（只会误报）。
- 遗留 TextIn 整文档解析没有逐页路由记录，需由适配代码合成 `reasons`（如 `legacy_textin_full_doc`），否则 P1 会拒绝。
- 页数 `page_count` 缺失时无法发现缺页，只出告警。
