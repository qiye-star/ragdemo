# 盲标正文题集（2026-10-14）

## 1. 为什么要这套题

重排丰富输入（`rerank_rich_input`）现在默认打开。它的收益已经在两套题上测过：100 道自动题（`auto:`）和 62 道盲标表格题（`blindmodel:tbl-v1`）。但非表格内容——公告正文、定期报告段落、章程和制度条款、律师意见、8-K 正文——只有自动题里的 71 道 `other/auto`。这些题是模型看着段落写的，而新的重排输入正好带上了文档标题和章节路径，所以 other/auto 的涨幅里同样可能有“自己出题自己考”的成分。

这套题照搬表格题集的做法（`盲标表格题集.md`），只是换成正文。它的作用是单独测量重排输入对非表格检索的影响。作者如实记为 `blindmodel-text:text-v1`，**不是人工题**。

## 2. 怎么做的

**挑源块。** 只用现行叶子块（`is_leaf`，`superseded_at IS NULL`），块类型为段落。库里现行叶子块没有单独的标题或列表类型，标题只出现在章节路径里。已被其他评测题当作 gold 的块不选作出题源，这样三套题互相独立。按文档、公司、文档类别、期别分层挑选，共 70 个源块，来自 45 份文档。新解析的文档（doc_id ≥ 567，含英伟达 8-K doc 622；567–570 和 doc 8 已被取代，现行版本是 618–622）占 51 题。寒武纪 doc 7 没有源 PDF（`raw_ref` 为空），没有用。

**出题（第一遍）。** 只看块的原文（`content`），**没有读描述（`content_desc`）**。问法按分析师的口吻，不照抄原文，例如“智能体相比聊天机器人会让 Token 用量放大多少倍”（原文是 Agent / Chatbot），“总经理办公会单笔能自行拍板的投资额度上限”。题型分四类：

- 事实查询：谁、哪天、多少；
- 事件：宣布了什么、选了谁；
- 条款：章程、议事规则、内审/关联交易/信披暂缓制度里的条件和规则；
- 跨期：同一事项在不同期别各出一题，例如 2022、2023、2024、2025 各年的分红方案，IDC 2024Q3 和 2025Q3 服务器出货增速，2022、2023、2024 各年的快报净利润，2023 年和 2026 年两次临时股东大会的登记日。

每个答案里的数字都用脚本核对过：既要在源块里，也要在源 PDF 文字层里。只有一处例外：doc 575 内控审计报告是扫描件，没有文字层，就把 PDF 第 3 页渲染出来人工核对了。70 题全部通过。

**复核（第二遍）。** 另起两个独立的模型会话，各拿 35 题，只给题目文字。复核方看不到第一遍的答案、源块和中间文件，也不许读描述。它们自己从库里和源 PDF 找答案，列出**所有**能单独回答该题的现行块（包括后续报告里的“上年同期”、表格块、会议资料里的重复段落、律师意见），把口径相近但不对的块另列为近似干扰块，并标出含糊、拆分、标签泄漏、无法回答等问题。

**合并规则。** 两遍答案一致才保留，gold 取复核方列出的块。复核标出问题的题，按复核方给的改写建议改写。

复核方指出的几个值得注意的地方，照原样保留：

- **T30 源文件里有错标。** 2026 年半年度业绩预告第 3 项（块 2194，扣非口径）原文写的是“扣除股份支付的影响后，预计……归属于母公司所有者的净利润 198,000–217,000 万元”。这是 PDF 文字层的原文，实际应是扣非数字。题目问“剔除股份支付后的归母净利润”，正确答案在 2193（217,000–230,000 万元），2194 只算干扰块。
- **快报口径和审定口径分开。** T12、T16、T20 问业绩快报里的净利润。年报审定数（例如 2022 年 80,354.01 万元对快报 80,200.58 万元）只算近似干扰块，不算 gold。
- **T25 的源块 1700 里没有写公司名**，公司和会议只能从文档标题看出来。题目保留，它正好检验标题进入重排输入的作用。

## 6. 怎么用

```bash
# C1（免费）
uv run --no-sync ragdemo eval run --models mock --no-rerank --w-vec 0 --author-prefix blindmodel-text: --label text-blind-C1
# C2（付费，需批准）。现在默认开丰富输入，对照组要显式关掉
uv run --no-sync ragdemo eval run --models siliconflow --rerank --vector-backend pg --no-rerank-rich-input --author-prefix blindmodel-text: --label text-blind-C2-off
uv run --no-sync ragdemo eval run --models siliconflow --rerank --vector-backend pg --author-prefix blindmodel-text: --label text-blind-C2-rich
```

`--author-prefix` 的实现是 `author LIKE '<前缀>%'`。`blindmodel-text:text-v1` 不以 `blindmodel:` 开头（第 11 个字符是 `-` 不是 `:`），所以 `--author-prefix blindmodel:` 仍然只选中 62 道表格题，`--author-prefix blindmodel-text:` 只选中这 70 题。前缀里没有 `_` 或 `%` 这类通配符。

## 7. 需要注意的地方

1. **命令行还不能用这个来源导入。** `evals/cli.py` 里 `label-import --origin` 的可选值写死为 `human|blindmodel`。本次 cli.py 正被别人修改，所以没有动它。建议之后把选项改成取 `ORIGIN_NOTES` 的键。
2. **分组名会显示成 `other/human` 和 `table/human`。** `evals/grouping.py` 把凡是不以 `auto:` 开头的作者都归为 `human`，并按 gold 里有没有表格块来分 table / other。所以只跑这套题时，会出现 `other/human` n=63 和 `table/human` n=7。后者 n<10，不进门槛。如果不带前缀一起跑，这 7 道题会和 62 道表格题混在同一个 `table/human` 组里。要不要给盲标正文题单开一个分组，由负责人决定；本次没有改分组代码。
3. **不带 `--author-prefix` 的 `eval run` 现在会跑 232 题**（100 道 auto、62 道盲标表格题、70 道盲标正文题），总体指标和以前的运行不可比。
4. **不是人工题。** 出题和复核都是同一类模型，只是不同的会话。独立性比人工加模型的组合弱，可能一致地犯同样的错。
5. **公司集中。** 海光占 67%。浪潮的旧文档只有 1 题，因为浪潮的旧正文块大多已被自动题用作 gold。英伟达只有一份 8-K（4 题）。题目是中文，英伟达 8-K 原文是英文，这 4 题同时考了跨语言检索。
6. **没有单独的标题块。** 库里的现行叶子块里没有标题或列表类型，标题只以章节路径的形式进入重排输入。所以这套题测不到“只命中标题”这种情况。
7. **题目里有些模板化很强的原文**，例如独立董事声明、内控审计意见、股东会登记办法，同类文字在多份文档里反复出现。复核方已经把能单独回答的重复块都列进 gold，期别或公司不同的列为干扰块。但各期措辞完全相同的块，仍然只能靠问题里的公司名和日期来区分。
