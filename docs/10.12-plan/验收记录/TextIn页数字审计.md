# TextIn 页数字审计（W2，零成本、只读）

日期：2026-10-13。脚本：`scripts/audit_textin_pages.py`（确定性；逐页 TSV 写到 `data/experiments/textin-page-audit-<日期>.tsv`，被 git 忽略）。辅助函数：`packages/ragdemo/src/ragdemo/parse/textin_audit.py`，测试 `tests/parse/test_audit_textin_pages.py`（15 例）。
未调 TextIn / LLM / 嵌入，库只读（SELECT）。本文只记计数与数字取值，不复制文档原文。

## 1. 口径

- **审计对象 = 现行版**：`core.document` 中 `parse_engine LIKE 'textin%'` 且 `superseded_at IS NULL` 的行，**31 份**，每个 `content_hash` 恰好一行（已核：无重复）。另 21 行是被取代的旧版（同一份缓存 JSON 重新切块，`superseded_at` 非空），不重复审计。缓存 JSON 路径 = `parse/textin/<content_hash>/<参数指纹>.json`，指纹取自 `parse_engine` 的 `+` 之后。
- 31 份 PDF 实际 **182 页**（任务里的"约 308 页"在库里对不上，与《已解析表格审计》§0 一致）。
- **TextIn 侧"入库内容"** = `blocks_from_detail` 会入库的条目（`content != 1`）：正文/标题/image 条目取 `text`，表格按 `cells[]` 重建，**合并单元格展开成重复值**（与 `table_markdown` 一致）。跨页表的格子**按格自己的 `page_id` 归页**（库里整张表只记首页）。页眉页脚（`content == 1`）单独统计，不算入库内容。
- **文字层** = pdfplumber（`parse/local/layout.extract_pages`）对原 PDF 的每页文字。
- **P3 判定**：每页构造 `PageInput(tier="L3", engine=<parse_engine>, reasons=("legacy_textin_full_doc",), tier_verdict="not_run", page_kind="legacy_unclassified")`，调用 `acceptance.check_page` 取 P3；文档级结论用 `verdict_for_document`（`DocumentMeta.page_count` 取库内值，`known_at_unchanged` 本审计无法核对、按未改处理；`coverage_threshold=None`，P4 仅告警）。脚本内对每页断言 P3 的 `count` 等于独立计算的多重集合差。
- P3 只验"入库数字 ⊆ 文字层数字"，所以**另算反向**：文字层有而入库内容没有的数字，按 页眉页脚 → 图表碎片（`strip_charts` 的剥离文字）→ 落在 TextIn 表格框内 → 其他 归类。
- **措辞提醒**：下面说的"未溯源/invented"指**数字不在文字层里**，不等于数字是错的。多数是图片里的字被 OCR 出来（图片内容人眼可见、只是 PDF 文字层没有）。本次抽样**没有发现凭空捏造**。

| unverifiable_scan（无文字层，无法核对） | 8 | 4% |

|---|---|---|---|

## 3. 未溯源数字的类别（804 个，互斥分类，按先到先得）

| 类别 | 个数 | 涉及页 / 文档 | 性质 |
|---|---|---|---|
| merge_expansion：合并单元格展开成重复值 | 461（57%） | 30 页 / 13 份 | **产物缺陷，不是内容问题**：`table_markdown` 为检索把合并格复制到每个被覆盖的格，P3 的多重集合比较会多算；数字本身在原文里 |

## 4. 结论：现有已解析语料满足溯源规则的比例

按 CLAUDE.md §0（每个数字必须可溯源）与 P3 的严格读法：

- **文档**：14 / 31（45%）整份可核对且通过，**全是 1–5 页的短公告（39 页）**；16 / 31（52%）为 `textin_unverified`；1 / 31（3%）为 `accepted_with_scan`（仍有 103 个数字没有任何核对手段，不应视为"已验证"）。
- **页**：124 / 182（68%）通过；50（27%）有不在文字层的数字；8（4%）无文字层。
- **体量**：年报摘要 546 与长公告 558 是未过的大头；三大表类内容的未过页几乎都是 merge/spacing 这种"产物缺陷"，而不是内容错误。
- 严格按字面：**S5 已触发**（`textin_unverified` 普遍：16/31 文档、50/182 页 `unverified_numbers > 0`），"已验收"的存量不能整体当作满足 §0。但缺陷的**性质**很不一致：57% 是我们自己展开合并格造成的假阳性，7% 是 TextIn 的空白缺陷（可确定性修复），29% 是图片 OCR（真的无法用文字层核对），其余是页码偏移与杂项。**真正需要降级处理的只有图片 OCR（及无文字层的扫描页）。**

## 5. 建议（不重解析、不调 TextIn，全部可用缓存 JSON 零成本完成）

1. **先定性、后处置**：S5 的处置决策按下表执行，优先于任何降本工作。
   - 图片 OCR 数字（235 个 / image 条目）：**块级标记**——为每个 `type=image` 来源的块打上"数字来源=图片 OCR，未经文字层核对"，生成/引用时按 §0 一律标注 `推断`，不得绑定为"已验证"的 `[block_id | page]`。可从缓存 JSON 的 `type` / `sub_type`（chart 等）确定性回填，无需重解析。
   - 扫描文档 575：**降级**为"数字不可引用"（只能作为全文参考，任何数字都标 `推断`），直到有 L2 双引擎或人工核对手段。
   - 带 spacing 缺陷的块（16 页 / 14 份）：用 `heal_spacing` 之类的确定性规则**在展示/引用层规整**，并在检索入库侧单独立项（需走评测，§1.4，因为改变了切块文本）；规整后数字在文字层里，可回到 `accepted`。
   - 页码归属偏移（14 页 / 6 份，23 个数字）：**引用处理**——跨页段落/表格的引用不得只给首页：记录页跨度，或验证时对 ±1 页取文字层；这是 `[block_id | page]` 的准确性问题，不是数字问题，建议 W1 的落库字段加 `page_end`。
2. **P3 的 TextIn 适配规则**（改调用方，不改 `acceptance.py` 的纯函数）：P3 对 TextIn 页应喂**不展开合并格**的表格文本（或用 `table_html` 去重后文本），否则 461 个假阳性会把所有带合并格的表永远打成 `textin_unverified`。展开重复值仍保留给检索，但不应参与溯源比对。
3. **把审计固化为入库后检查**：新入库的 TextIn 文档在落库前跑同一套逐页 P3，结果写入 W1 设计的逐页记账字段；`textin_unverified` 的文档在引用链路里按上面第 1 条处理，而不是默默当作已验收。
4. **口径提醒**：本审计只验"数字是否出现在该页文字层"，不验数字的行/列/期别归属，也不验图片内 OCR 对错（无参照）；"每月抽 30 个数字 + 15 页阅读顺序"的人工抽查仍需常设（见《逐页验收定义》§4）。

## 6. 复现

```bash
set -a && . ./.env && set +a && uv run --no-sync python scripts/audit_textin_pages.py
```

约 25 秒。输出：终端汇总 + `data/experiments/textin-page-audit-<日期>.tsv`（逐页：未溯源个数与最多 5 个取值示例、各类别个数、页眉页脚数字数、反向丢失的分类）与 `-docs.tsv`（逐文档结论）。
