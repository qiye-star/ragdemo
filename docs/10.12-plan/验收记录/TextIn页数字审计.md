# TextIn 页数字审计（W2，零成本、只读）

日期：2026-10-13（含控制者批准的"不展开合并格"更正）。脚本：`scripts/audit_textin_pages.py`（确定性；逐页 TSV 写到 `data/experiments/textin-page-audit-<日期>.tsv`，被 git 忽略）。辅助函数：`packages/ragdemo/src/ragdemo/parse/textin_audit.py`，测试 `tests/parse/test_audit_textin_pages.py`。
未调 TextIn / LLM / 嵌入，库只读（SELECT）。本文只记计数与数字取值，不复制文档原文。**下文每个数字都给"新（更正后）"与"旧（首版，合并格展开）"两列。**

## 1. 口径

- **审计对象 = 现行版**：`core.document` 中 `parse_engine LIKE 'textin%'` 且 `superseded_at IS NULL` 的行，**31 份**，每个 `content_hash` 恰好一行（无重复）。另 21 行是被取代的旧版（同一缓存 JSON 重新切块），不重复审计。缓存 JSON = `parse/textin/<content_hash>/<参数指纹>.json`。
- 31 份 PDF 实际 **182 页**（"约 308 页"在库里对不上，见《已解析表格审计》§0）。
- 文字层 = pdfplumber；TextIn 侧 = `content != 1` 的条目；页眉页脚（`content == 1`）单独统计。跨页表的格子按**格自己的 `page_id`** 归页。
- **更正：表格按"不展开"文本比较。** 方法：缓存 JSON 的每个 cell **都带 `row_span` / `col_span`**（已验 31 份文档全部表格的全部 cell），所以直接取每个 cell 自己的 `text` **只算一次**；旧口径把它复制 `row_span×col_span` 份（与入库 Markdown 的合并格展开一致）。**未使用"按位置去重"的退路**。手工核了 3 张含合并格的表（取文字层同页的数字出现次数对照）：
  - doc 566 第 5 页：1 个横向合并的数字格，不展开 9 个数字、展开 10 个；该数字在文字层出现的次数与"只算一次"相符。
  - doc 266 第 2 页：6 个横向合并（col_span=2）的格，不展开 9 个、展开 17 个；文字层中 801、0531、85106229、000977 的次数与每格算一次一致（展开会各多 1 个）。
  - doc 566 第 1 页：6 个合并的金额格，不展开 25、展开 31；每个金额在文字层恰好出现 1 次。
  - 这 3 张表里"不展开"的次数都等于文字层次数，展开口径则多出来，所以更正正确。
- P3：每页 `PageInput(tier="L3", engine=<parse_engine>, reasons=("legacy_textin_full_doc",), tier_verdict="not_run", page_kind="legacy_unclassified")` 调 `acceptance.check_page`，文档级用 `verdict_for_document`（`known_at_unchanged` 按未改处理；`coverage_threshold=None`）。脚本对每页断言 P3 的 `count` 等于独立算的多重集合差。同一份数据跑三遍：**旧**（展开）、**新**（不展开）、**新+比较时重接空白**（`heal_spacing` 只作用于比较用的文本副本，库里存的文本和缓存 JSON 一字不动）。
- 反向（文字层有而入库没有）按 页眉页脚 → 图表碎片 → 表格框内 → 其他 归类；该统计也改用不展开文本（展开的重复值会掩盖丢失）。
- **措辞提醒**："未溯源"= 数字不在该页文字层，不等于数字是错的。本次抽样（约 30 例）**没有发现凭空捏造**。

## 2. 结果：旧 → 新

逐页（182 页）：

| P3 状态 | 旧（展开） | **新（不展开）** | 新 + 比较时重接空白 |
|---|---|---|---|
| pass | 124 (68%) | **142 (78%)** | 155 (85%) |
| fail | 50 | **32** | 19 |
| unverifiable_scan | 8 | 8 | 8 |

文档级结论（31 份）：

| 结论 | 旧 | **新** | 新 + 重接空白 |
|---|---|---|---|
| accepted | 14（39 页，全是 1–5 页短公告） | **14** | 20（79 页） |
| accepted_with_scan | 1（doc 575） | 1 | 1 |
| textin_unverified | 16 | **16** | 10 |
| 其他（rejected / partially_accepted / empty） | 0 | 0 | 0 |

**不展开合并格并没有改变任何文档的结论**：此前 13 份有合并格重复的文档，同时也都有别的未溯源数字（空白缺陷、图片 OCR、页码偏移等）。展开重复只是把"未溯源数字个数"夸大了；真正让文档过关的是**重接空白**（再多 6 份文档转为 accepted）。

数字（可核对页上的入库数字）：

| | 旧 | **新** |
|---|---|---|
| 可核对页上的入库数字 | 5060（展开） | **4599**（不展开） |
| 不在文字层的数字 | 804（15.9%） | **343（7.5%）** |
| 重接空白后仍不在文字层 | – | **287（6.2%）** |

**满足 §0 溯源规则的覆盖率（新）**：
- 文档：14 / 31 = **45%** 整份通过（旧：同为 45%）；重接空白后 20 / 31 = **65%**；另有 1 份（3%）为 `accepted_with_scan`，其 103 个数字没有任何核对手段，不应视为已验证。
- 数字：可核对数字里 **92.5%**（4256 / 4599）在文字层；重接空白后 **93.8%**（4312 / 4599）；扫描页 103 个数字不计入分母。
- 页：78% → 重接空白后 85%。

反向（文字层有而入库没有，300 个，口径不变）：页眉页脚 249（TextIn 标为页眉页脚而丢弃，合法）、表格框内 30、其他 21（集中在 10 页，主要是页码归属偏移）、图表碎片 0（`strip_charts` 在这 182 页没有剥离文字）。

## 4. 结论

- **S5 仍然字面触发**（新口径 16/31 文档、32/182 页有数字不在文字层），但更正后性质清楚得多：343 个里 59 个只是 TextIn 的空白缺陷（比较时重接即消除），461 个"展开重复"是我们比较口径的问题（已消除，不是数据问题）。
- **重接空白后仍不能自动核对的 287 个（6.2%）**：
  - **真正无法用文字层核对**：图片 OCR 235 + 图表标题年份 7 + 信头/日期图片 20 + 列表编号粘连 2 + 格式差 2 + 约 3 个重接副作用，合计约 270，集中在 546、558、572 三份，外加整份扫描文档 575 的 103 个。
  - **可核对、只是页码归属偏了**：18 个（adjacent_page），把取证范围放宽到 ±1 页即可核对，不是数字问题。
- 因此**真正需要降级/标注的**只有：图片来源的数字（546、558、572）与扫描文档 575；其余 28 份文档的数字在文字层能找到（经重接空白，20 份整份通过，另 8 份只剩页码偏移/格式差/少量图片文字）。

## 5. 建议（不重解析、不调 TextIn，全部可用缓存 JSON 零成本完成）

1. **图片 OCR 数字块级标记**：为 `type=image`、`sub_type=image_title` 及信头/图片内文字块（可由缓存 JSON 的 `type`/`sub_type` 确定性回填）打上"数字来源=图片 OCR，未经文字层核对"，生成/引用时按 §0 一律标 `推断`，不得绑定为已验证的 `[block_id | page]`。
2. **扫描文档 575 降级**：数字一律不可引用（仅作全文参考，数字标 `推断`），直到有 L2 双引擎或人工核对。
3. **P3 的 TextIn 适配**（改调用方，不改 `acceptance.py` 的纯函数）：喂**不展开合并格**的表格文本；比较前对文本副本做 `heal_spacing`。展开值与带空格的原文仍保留给检索，只是不参与溯源比对。若要修正入库文本本身，须单独立项并跑评测（§1.4）。
4. **页码归属**：引用跨页段落/表格时记录页跨度，或验证时对 ±1 页取文字层；建议 W1 落库字段加 `page_end`。
5. **固化**：新入库的 TextIn 文档在落库前跑同一套逐页 P3，结果写入 W1 的逐页记账字段；`textin_unverified` 的文档在引用链路里按 1/2 处理，而不是默默当作已验收。
6. 局限：本审计只验"数字是否出现在该页文字层"，不验行/列/期别归属，也不验图片内 OCR 对错；"每月抽 30 个数字 + 15 页阅读顺序"的人工抽查仍需常设（《逐页验收定义》§4）。

## 6. 复现

```bash
set -a && . ./.env && set +a && uv run --no-sync python scripts/audit_textin_pages.py
```

约 25 秒。输出终端汇总（新 / 旧 / 新+重接空白三套文档结论）与 `data/experiments/textin-page-audit-<日期>.tsv`（逐页，含 `invented_old_expanded` 旧口径个数与各类别个数、反向丢失分类）、`-docs.tsv`（逐文档，含 `verdict`、`verdict_old_expanded`、`verdict_healed`）。
